# 이진탐색: 경계가 줄어드는지 확인하기

정렬된 목록에서 목표를 찾을 때 이진탐색은 매번 남은 후보의 절반가량을 제외한다. 핵심은 가운데 값을 고르는 것보다, 제외할 수 있는 범위를 정확히 판단하는 것이다.

## 구현 전 약속

- 입력은 오름차순으로 정렬된 정수 목록이다.
- lo와 hi는 아직 검사할 구간의 양 끝을 포함한다.
- 결과는 값이 아니라 0부터 시작하는 인덱스다. 없으면 -1을 반환한다.
- 중복값이 있으면 일치하는 위치 중 하나를 반환한다. 첫 위치나 마지막 위치를 보장하지 않는다.

## 최소 구현과 재현 테스트

```python
def binary_search(values, target):
    lo, hi = 0, len(values) - 1
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        value = values[mid]
        if value < target:
            lo = mid + 1
        elif value > target:
            hi = mid - 1
        else:
            return mid
    return -1


cases = [
    ([], 9, -1),
    ([9], 9, 0),
    ([9], 4, -1),
    ([2, 6, 11, 19, 27], 2, 0),
    ([2, 6, 11, 19, 27], 27, 4),
    ([2, 6, 11, 19, 27], 19, 3),
    ([2, 6, 11, 19, 27], 8, -1),
    ([2, 6, 11, 19, 27], 0, -1),
    ([2, 6, 11, 19, 27], 30, -1),
]
for values, target, expected in cases:
    assert binary_search(values, target) == expected

values = [2, 6, 6, 6, 11]
index = binary_search(values, 6)
assert 0 <= index < len(values) and values[index] == 6
print("PASS: 9 exact-index cases and 1 duplicate-validity case")
```

Python 3에서 위 블록을 실행하면 마지막 PASS 문장이 출력된다. 2026-10-25에 이 코드와 10개 검사를 실제 실행해 통과를 확인했다. 이는 아래 경계 사례의 확인이며, 모든 입력에 대한 실험적 검증을 뜻하지 않는다.

## 오류 점검 체크리스트

- [ ] 정렬을 보장하는가? 함수가 입력을 몰래 정렬하면 원래 인덱스의 의미가 바뀐다.
- [ ] lo == hi일 때 남은 원소 하나도 검사하는가?
- [ ] 실패한 mid를 다음 구간에서 제외하는가? lo = mid처럼 그대로 남기면 반복이 멈추지 않을 수 있다.
- [ ] 빈 목록, 한 원소, 양 끝, 중간의 없는 값, 범위 밖 값을 검사했는가?
- [ ] 중복값 처리 계약을 테스트에도 반영했는가?
- [ ] 인덱스 접근 비용이 일정한 목록을 전제로 복잡도를 설명하는가?

후보 구간이 반복마다 줄어드므로 시간복잡도는 O(log n), 구현의 추가 공간은 O(1)이다. 반복문이 끝났을 때 lo > hi이면 후보가 남지 않은 상태다.
